2. **设备联网**。设备只有 USB NCM 链路，`wlp1s0` 未连接任何 AP，没有默认路由，
   `dnf` 连不上 COPR 和 Fedora 镜像。连 WiFi 需要凭据，未在自动化里处理。

3. **从 COPR run 重建完整发布链**：`build-rootfs → build-image → build-bundle
   → prepare-install`，所有输入用同一组精确 run id，最终
   `source-runs.json` 必须能追到同一套 RPM、内核、rootfs、image 和 UEFI。

4. **原始 GPT/UFS 冷启动验收**：`install-f2fs.py apply` 从原始分区表重新分区，
   按 `deploy-bundle` + `root-install` 刷写 `boot_b`、`sunuefi_esp`、
   `sunuefi_root`，不碰 `dtbo_b`、不擦 userdata。重启后必须进入 GNOME，并核对
   `uname -r`、`/usr/lib/modules/<release>`、`findmnt /` 为 F2FS、
   `systemctl --failed` 为空。

5. **Android ↔ Linux 往返**：从 Linux 返回 Android 能正常启动，再从 Android
   切回 Linux 仍进桌面；记录回滚路径 `fastboot set_active a`，以及 COPR 仓库
   停用和包回滚命令。

## 已知风险

- 设备当前 `dnf-makecache.service` 失败是网络不可达导致，不是包管理器故障。
- `piano-fedora-configs` 0.1.0-5 新增 COPR 仓库文件，但设备上装的是旧
  `piano-runtime`；新镜像会通过 `Obsoletes` 替换，旧系统需要重新部署才能拿到
  该仓库文件。
- `kernel-piano` 在 COPR 仓库里可下载但被默认排除。手动 `--enablerepo` 强装会
  让 ESP 与 rootfs 内核脱钩。
